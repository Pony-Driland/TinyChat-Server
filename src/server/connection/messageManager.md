# Message Manager — Socket.IO API

This document describes every Socket.IO event handled by
[`messageManager.js`](./messageManager.js): messages, history, dice and the purge tools.

Every handler follows the same contract:

- the payload is a plain object (`noDataInfo` rejects anything else);
- the last argument is the **acknowledgment callback** (`fn`);
- failures always answer `{ error: true, msg: string, code: number }`;
- the caller must be authenticated (`accountNotDetected`) and is rate limited per event.

## Common error codes

These codes are shared by several events, so they are not repeated in every table.

| Code | Meaning                                                                   |
| ---- | ------------------------------------------------------------------------- |
| `0`  | Incomplete/invalid payload (`sendIncompleteDataInfo`)                     |
| `0`  | No account detected (`accountNotDetected`, also sets `noAccount: true`)   |
| `1`  | Rate limit exceeded (`ratelimit: true`) — see [rate limits](#rate-limits) |

## Rate limits

Every event below is throttled by `createRateLimit` (see [`values.js`](./values.js)). The window is
`limits.RATE_LIMIT_TIME` (ms) and the amount comes from `config.ini`.

| Limiter                       | Config key        | Used by                                                                        |
| ----------------------------- | ----------------- | ------------------------------------------------------------------------------ |
| `userMsgIsRateLimited`        | `MESSAGES`        | `send-message`                                                                 |
| `userMsgEditIsRateLimited`    | `MESSAGES_EDIT`   | `edit-message`                                                                 |
| `userMsgDeleteIsRateLimited`  | `MESSAGES_DELETE` | `delete-message`, `purge-user-messages`, `delete-dice-roll`, `purge-user-dice` |
| `userMsgLoadIsRateLimited`    | `MESSAGES_LOAD`   | `load-messages`, `load-dice-history`                                           |
| `userDiceIsRateLimited`       | `DICE_ROLLS`      | `roll-dice`                                                                    |
| `userUpdateDiceIsRateLimited` | `DICE_ROLLS`      | `set-dice`                                                                     |

## Messages

### `send-message`

Sends a message to a room, stores it in `history` and broadcasts `new-message` to the room.

**Payload**

```json
{
  "roomId": "lobby",
  "message": "Hello world",
  "isModel": false,
  "tokens": 12,
  "model": "gpt-4o-mini",
  "hash": "9f2c...",
  "errorCode": null
}
```

| Field       | Type      | Required | Description                                      |
| ----------- | --------- | -------- | ------------------------------------------------ |
| `roomId`    | `string`  | ✅       | Room that receives the message                   |
| `message`   | `string`  | ✅       | Message text (non-empty)                         |
| `isModel`   | `boolean` | ✅       | `true` when the message was generated by a model |
| `tokens`    | `number`  | ➖       | Token count reported by the model                |
| `model`     | `string`  | ➖       | Model identifier                                 |
| `hash`      | `string`  | ➖       | Content hash                                     |
| `errorCode` | `string`  | ➖       | Error code of a failed generation                |

**Acknowledgment**

```json
{ "id": "8f14e45f...", "date": 1730419200000, "chapter": 1 }
```

**Broadcast — `new-message`**

```json
{
  "roomId": "lobby",
  "id": "8f14e45f...",
  "userId": "alice",
  "isModel": false,
  "chapter": 1,
  "text": "Hello world",
  "date": 1730419200000,
  "tokens": 12,
  "hash": null,
  "model": null,
  "errorCode": null,
  "edited": 0
}
```

**Errors**

| Code | Meaning                                                                                 |
| ---- | --------------------------------------------------------------------------------------- |
| `1`  | `message` is longer than `limits.MESSAGE_SIZE` (also returns `numbers: [MESSAGE_SIZE]`) |
| `2`  | Room not found                                                                          |
| `3`  | You are not in this room                                                                |
| `4`  | Not enough permissions (room in read-only mode, or `isModel` sent by a non-owner)       |
| `5`  | You are in read-only mode (no `roomPermissions` row)                                    |

> Only the **server owner** may send a message with `isModel: true`.

| `5`  | You are in read-only mode |

### `load-messages`

Paginated history with optional filters.

**Payload**

```json
{
  "roomId": "lobby",
  "page": 1,
  "perPage": 50,
  "text": null,
  "chapter": null,
  "start": null,
  "end": null,
  "userId": null
}
```

| Field           | Type             | Description                                                                            |
| --------------- | ---------------- | -------------------------------------------------------------------------------------- |
| `page`          | `number`         | Page, starting at `1`                                                                  |
| `perPage`       | `number \| null` | Page size. `null` loads everything (needs `server.load_all_history` or the room owner) |
| `text`          | `string \| null` | `LIKE %text%` filter                                                                   |
| `chapter`       | `number \| null` | Chapter filter                                                                         |
| `start` / `end` | `number \| null` | Date range (ms)                                                                        |
| `userId`        | `string \| null` | Author filter                                                                          |

**Acknowledgment**

```json
{
  "success": true,
  "page": 1,
  "totalItems": 85,
  "totalPages": 2,
  "messages": []
}
```

**Errors**

| Code | Meaning                                                             |
| ---- | ------------------------------------------------------------------- |
| `1`  | Room not found                                                      |
| `2`  | You are not in this room                                            |
| `3`  | `text`/`userId` longer than the configured limit                    |
| `4`  | `perPage` is bigger than `limits.HISTORY_SIZE`                      |
| `5`  | `perPage` is smaller than `1`                                       |
| `6`  | Loading everything is disabled and the caller is not the room owner |
| `7`  | Read-only guest trying to use filters or an older page              |

> A read-only guest may only load **page 1 with no filters**, so the room never looks empty.

## Dice

### `roll-dice`

Rolls one or more dice and broadcasts `roll-result`.

**Payload**

```json
{
  "roomId": "lobby",
  "canZero": false,
  "dice": [6, 6, 20],
  "modifiers": [{ "index": 0, "original": "1d6", "expression": "1d6+2" }],
  "diceSkin": {
    "img": "data:image/png;base64,...",
    "border": "#000",
    "bg": "#fff",
    "text": "#111",
    "selectionBg": "#eee",
    "selectionText": "#000"
  }
}
```

| Field       | Type                                     | Description                                          |
| ----------- | ---------------------------------------- | ---------------------------------------------------- |
| `dice`      | `number[]`                               | Sides of each die (non-empty)                        |
| `canZero`   | `boolean`                                | When `true` the result is `0..n-1` instead of `1..n` |
| `modifiers` | `Array<{ index, original, expression }>` | Exactly three string/number fields per entry         |
| `diceSkin`  | `object`                                 | Optional. Falls back to the skin saved by `set-dice` |

**Acknowledgment**

```json
{ "success": true, "results": [{ "value": 4, "sides": 6 }], "id": "a1b2c3" }
```

**Broadcast — `roll-result`**

```json
{
  "date": 1730419200000,
  "results": [{ "value": 4, "sides": 6 }],
  "modifiers": [{ "index": 0, "original": "1d6", "expression": "1d6+2" }],
  "skin": {
    "img": null,
    "border": null,
    "bg": null,
    "text": null,
    "selectionBg": null,
    "selectionText": null
  },
  "canZero": false,
  "userId": "alice",
  "roomId": "lobby",
  "id": "a1b2c3"
}
```

**Errors**

| Code | Meaning                                     |
| ---- | ------------------------------------------- |
| `1`  | Room not found                              |
| `2`  | You are not in this room                    |
| `3`  | Invalid dice configuration (negative sides) |
| `4`  | You are in read-only mode                   |

---

### `set-dice`

Stores the visual skin used by the next dice rolls.

**Payload**

```json
{
  "diceSkin": {
    "img": "string",
    "border": "string",
    "bg": "string",
    "text": "string",
    "selectionBg": "string",
    "selectionText": "string"
  }
}
```

**Acknowledgment**

```json
{ "success": true }
```

Every field is trimmed and truncated by its own limit:

| Field           | Config key                  |
| --------------- | --------------------------- |
| `img`           | `DICE_IMG_SIZE`             |
| `border`        | `DICE_BORDER_STYLE`         |
| `bg`            | `DICE_BG_STYLE`             |
| `text`          | `DICE_TEXT_STYLE`           |
| `selectionBg`   | `DICE_SELECTION_BG_STYLE`   |
| `selectionText` | `DICE_SELECTION_TEXT_STYLE` |

### `delete-dice-roll`

Deletes a single dice roll. **The author can never delete their own roll** — only the room staff
can, which keeps the history trustworthy.

**Payload**

```json
{ "roomId": "lobby", "rollId": "a1b2c3" }
```

**Acknowledgment**

```json
{ "success": true, "roomId": "lobby", "id": "a1b2c3" }
```

**Broadcast — `dice-roll-deleted`**

```json
{ "roomId": "lobby", "id": "a1b2c3" }
```

**Errors**

| Code | Meaning                  |
| ---- | ------------------------ |
| `1`  | Room not found           |
| `2`  | You are not in this room |
| `3`  | Dice roll not found      |
| `4`  | Not enough permissions   |

## Purge

### `purge-user-messages`

Deletes every message of an account inside a room, following a time window. The rows are copied to
`historyDeleted` first, exactly like `delete-message`.

**Payload**

```json
{ "roomId": "lobby", "userId": "bob", "mode": "days", "amount": 7 }
```

| `mode`  | `amount` | Effect                                         |
| ------- | -------- | ---------------------------------------------- |
| `none`  | —        | No-op, answers `{ success: true, deleted: 0 }` |
| `hours` | `n`      | Deletes everything from the last `n` hours     |
| `days`  | `n`      | Deletes everything from the last `n` days      |
| `count` | `n`      | Deletes the `n` most recent messages           |
| `all`   | —        | Deletes everything                             |

**Acknowledgment**

```json
{ "success": true, "deleted": 12, "ids": ["8f14e45f..."] }
```

**Broadcast — `messages-purged`**

```json
{ "roomId": "lobby", "userId": "bob", "ids": ["8f14e45f..."] }
```

**Errors**

| Code | Meaning                                           |
| ---- | ------------------------------------------------- |
| `1`  | Room not found                                    |
| `2`  | Only the room owner or the server owner can purge |

---

### `purge-user-dice`

Same as `purge-user-messages`, but for the `diceHistory` table. There is **no** safety backup: the
rolls are gone.

**Payload**

```json
{ "roomId": "lobby", "userId": "bob", "mode": "count", "amount": 10 }
```

**Acknowledgment**

```json
{ "success": true, "deleted": 10, "ids": ["a1b2c3"] }
```

**Broadcast — `dice-rolls-purged`**

```json
{ "roomId": "lobby", "userId": "bob", "ids": ["a1b2c3"] }
```

**Errors**

| Code | Meaning                                           |
| ---- | ------------------------------------------------- |
| `1`  | Room not found                                    |
| `2`  | Only the room owner or the server owner can purge |

## Events emitted

| Event               | Sent to | Description                          |
| ------------------- | ------- | ------------------------------------ |
| `new-message`       | room    | A message was created                |
| `message-updated`   | room    | A message was edited                 |
| `message-deleted`   | room    | A message was deleted                |
| `messages-purged`   | room    | A bulk delete of messages happened   |
| `roll-result`       | room    | A dice roll happened                 |
| `dice-roll-deleted` | room    | A dice roll was deleted              |
| `dice-rolls-purged` | room    | A bulk delete of dice rolls happened |

> `new-message` and `message-updated` go through `createStreamBroadcast()`, so they may arrive
> chunked. Every other event is emitted untouched.

## Chunked transfer

Socket.IO serializes the whole packet on the server and parses it back on the client, both on the
main thread, and the transport rejects anything above 1 MB. A multi-megabyte roleplay message would
freeze the tab, so [`stream.js`](./stream.js) splits it up.

Payloads **up to 256 KB** (`STREAM_THRESHOLD`) are emitted untouched. Anything bigger is serialized
once and sliced into 64 KB (`STREAM_CHUNK_SIZE`) chunks:

| Event          | Payload                                               |
| -------------- | ----------------------------------------------------- |
| `stream-start` | `{ id, event, total, size }`                          |
| `stream-chunk` | `{ id, index, data }` — `data` is a slice of the JSON |
| `stream-end`   | `{ id }`                                              |

The client concatenates every `data` in `index` order and only then parses the JSON, so the event
name in `stream-start` tells which handler should receive the rebuilt payload.
